## **배경**
저는 `Ubuntu`를 로그인 한 후에 블로그 작업이든, 개발 작업이든 거의 일관된 프로그램들과 창 배치로 띄어두고 작업을 시작합니다. 그런데 매번 해당 프로그램들을 일일이 클릭하고 `SUPER` 키를 눌러서 세팅하는 것이 정말 귀찮았습니다. 시간이 되면 자동 세팅을 할 수 있는 스크립트를 작성해야겠다고 생각했었습니다.

근데, 생각보다 시간이 잘 나지도 않고 제 요구사항을 한두가지씩 적다보니까 생각보다 많아서 코드 작성이 꽤 오래걸릴 것 같았습니다. 그래서 `ChatGPT Plus`를 사용해서 코드를 작성했습니다. 최근에 `LLM`를 사용하여 개발을 얼마나 잘 할 수 있는 가도 중요한 요소로 자리잡은 것 같습니다.<br><br>

> **그래서 이번 기회에 재부팅 시, 자동으로 프로그램을 실행하고 프로그램 창을 배치하는 스크립트를 개발할 뿐만 아니라 `LLM`을 사용한 개발이 얼마나 효율적인지 확인해보도록 하겠습니다.**

## **프롬프트 입력**
가장 처음에는 제가 원하는 바를 먼저 단순하게 물어봤습니다.

---
Q(나)
: 우분투에서 데스크탑 창 배치를 시작할 때마다 불러오고 싶은데 방법이 없을까?

A(ChatGPT 답변 요약)
: [Another Window Session Manager](https://github.com/nlpsuge/gnome-shell-extension-another-window-session-manager) 설치 추천

---

답변으로는 비슷한 기능을 제공하는 프로그램이 있다고 하네요. 그럼 꼭 스크립트를 따로 작성 안 해도 되겠다 싶었는데...

제가 사용하는 `Ubuntu 20.04`에는 사용이 불가하네요. `Ubuntu 20.04`는 `GNOME Shell 3.36.9`이 가장 마지막 버전이라서 [Another Window Session Manager](https://github.com/nlpsuge/gnome-shell-extension-another-window-session-manager)을 사용할 수 없네요.

그럼 제 개발환경을 알려줌으로서 저에게 맞는 방법이 있는지 확인해보겠습니다.

---
Q(나)
: GNOME Shell 3.36.9, x11, 20.04

A(ChatGPT 답변 요약)
: `wmctrl`로 창 배치 스크립트를 만들고 로그인 시 실행하는 방식 추천, 어떻게 설정하면 좋은지 설명

---

`wmctrl`는 리눅스 `X11` 환경에서 명령어로 창 관리자를 제어하는 유닉스 명령어 도구입니다. 어떻게 설정하면 되는지 쭉 알려주는데, 앞서 입력한 내용이 너무 빈약하다 보니까 제가 원하는 스크립트를 작성해주지 않았습니다. 그래도 스크립트 초안을 보니까 어떤 기능을 추가할지 확실해졌습니다. 아래의 3가지 기능을 추가해주도록 하겠습니다.

1. 현재 배치되어 있는 프로그램(`Chrome`의 `URL`도 제대로 인식)과 각 프로그램 창의 위치를 기억하고 재부팅 시 활용하기
2. `wmctrl`를 통해서 좌표를 기억해서 배치하다 보니 깔끔하게 배치 되지 않는 문제가 발생하기 때문에 `SUPER` 키를 사용해서 배치시키기
3. 재부팅했을때, 저장한 프로그램들과 각 프로그램의 창 위치를 복원할 수 있도록 하기

위의 기능들을 추가해달라고 요청을 했습니다.

하지만 제대로 작동하지 않았습니다.

멀티 모니터를 판별하지 못하고 프로그램 창 위치도 제대로 찾지 못하는 문제가 발생한 것입니다. 아무리 코드 작성 능력이 좋아졌다고 해도 알아서 딱 만들어 주지는 않는 것 같습니다. 그래서 더 구체적인 규칙을 정해주기로 했습니다.

```
의도대로 잘 작동하는데 save하는 과정에서 추가하고 싶은 기능이 있어.

"현재 열린 창"을 파악하기 이전 단계에서 인식되는 모니터를 확인해줘 아래의 순서대로 확인해줘.(꼭 인터페이스로 표시할 필요 X)
1. xrandr를 통해서 모든 모니터의 상대적인 위치를 파악해줘.(ex. 지금 내 컴퓨터가 DP2가 왼쪽, DP0가 오른쪽에 있는 것을 xrandr 값을 가지고 파악할 수 있는 것 처럼)
2. n개의 모니터가 있으면 왼쪽부터 해서 1, 2, 3, ..., n 모니터로 번호를 매겨줘.

그 다음 "현재 열린 창" 단계에서는 열려있는 프로그램을 파악하고 내가 위치를 저장하고 싶은 프로그램을 선택하는 것은 그대로 유지할게.

근데 추가로 "프로그램 배치 위치 확인"을 하는 단계는 아래의 순서대로 작동시켜줘.
1. wmctrl를 사용해서 각 프로그램의 위치를 통해서 프로그램이 모니터의 좌, 우, 상, 하, 총 4개의 방향 중 어디에 배치되어 있는지를 판단해줘.
(ex. 1번 모니터의 '좌'에 chrome, 1번 모니터 '우'에 Visual code 이런 식으로)

"배치 번호 입력" 단계는 "프로그램 배치 위치 확인" 단계가 제대로 작동하면 필요 없어지는 단계야.

그럼 각 프로그램마다 속하는 모니터번호와 프로그램의 배치 위치를 알 수 있게 되었어.
이러한 정보를 활용하여 재부팅 했을때, 각 프로그램을 특정 커맨드로 배치할 수 있도록 할거야.
아래의 규칙을 따라 각 프로그램에 어떤 커맨드를 적용시킬지를 기록해줘.(꼭 인터페이스로 표시할 필요 X)
 
1. 1 ~ (n//2)번째 모니터에 배치되어있던 프로그램
	a. (Super_L+Left → Super_L+Left) X (n - 1) → Super_L+Left로 가장 왼쪽 모니터로 갈 수 있게 해줘.
	b. 프로그램이 1 ~ (n//2)번째 모니터 중 i번째 모니터에 속한 프로그램이라고 한다면 (Super_L+Right → Super_L+Right) X (i - 1)를 추가해줘.
	c. 만약에, 프로그램 위치가 '좌'라면, 커맨드를 추가할 필요 없어.
	d. 만약에, 프로그램 위치가 '우'라면, Super_L+Right를 추가해줘.
	e. 만약에, 프로그램 위치가 '상'이라면, Super_L+Up → Super_L+Up → Super_L+Up를 추가해줘.
	f. 만약에, 프로그램 위치가 '하'이라면, Super_L+Up → Super_L+Up → Super_L+Up→ Super_L+Down를 추가해줘.
2. (n//2 + 1) ~ n번째 모니터에 배치되어있던 프로그램
	a. (Super_L+Right → Super_L+Right) X (n - 1) → Super_L+Right로 가장 오른쪽 모니터로 갈 수 있게 해줘.
	b. 프로그램이 (n//2 + 1) ~ n번째 모니터 중 j번째 모니터에 속한 프로그램이라고 한다면 (Super_L+Left → Super_L+Left) X (n - j)를 추가해줘.
	c. 만약에, 프로그램 위치가 '좌'라면, Super_L+Left를 추가해줘.
	d. 만약에, 프로그램 위치가 '우'라면, 커맨드를 추가할 필요 없어.
	e. 만약에, 프로그램 위치가 '상'이라면, Super_L+Up → Super_L+Up → Super_L+Up를 추가해줘.
	f. 만약에, 프로그램 위치가 '하'이라면, Super_L+Up → Super_L+Up → Super_L+Up→ Super_L+Down를 추가해줘.

나머지는 기존과 비슷하게 작동시키면 될것 같아.
```

위의 규칙들을 프롬프트에 입력을 하니까 이제는 꽤 제 의도에 맞는 스크립트가 작성이 되었습니다. 자잘한 오류들은 있었지만 치명적이지는 않아서 해결하는데 크게 어렵지는 않았습니다.

## **마치며**
> **확실히 사전조사나 프로그램 스크립트의 초안을 작성하는데는 `LLM`가 최고입니다.**

아무래도 `Google` 서치를 하면 일일이 찾아보기 힘들고 영어로 작성된 게시물은 읽어보기 꺼려집니다. 이런저런 이유를 따져봤을때, `LLM`를 사용한 사전조사가 정말 유용한 것 같습니다. 당연히 더블체크는 중요합니다.

그리고 요구사항이 불분명한 경우에 스크립트 초안을 작성하는 것이 크게 도움이 되었습니다. 저는 개인적으로 요구사항을 처음부터 끝까지 모두 정하는 과정에서 오랜 시간을 투자하고 꽤 스트레스를 받습니다. 그런데 스크립트 초안을 딱 보여주니 제가 원하는 요구사항이 무엇인지 갈피를 빠르게 잡을 수 있었습니다. 당연히 작성해준 스크립트가 제 의도대로 작동하지 않는 경우가 있기도 하지만 이는 스크립트를 확인하고 규칙을 추가해주면 되는 일입니다.

또, 작성해준 프로그램 스크립트의 초안을 보면서 놀란 부분은 `Diagnostic Command`와 `Inspection Command` 기능을 알아서 넣어줬다는 점입니다. 제가 넣어달라고 요청을 하지 않았는데도 불구하고 `--show`, `--startup`과 같은 프로그램 진단 및 검사를 할 수 있는 명령어 기능을 넣어줬습니다. 덕분에 피드백하기도 쉬웠고 규칙 추가가 쉬었던 것 같습니다.

다음에도 이런 자잘한 코딩은 `LLM`의 도움을 받아서 작성할 것 같습니다.
